# Endpoint integration and security audit - 4 November 2026

This is a local source audit of `erjv-frontend` and the sibling `erjv-backend` working trees. It does not certify a deployed production service. This endpoint inventory did not change application or deployment state. The accompanying full audit ran mutation tests only in its dedicated local database, as recorded in the main report.

## Evidence and scope

The inventory covers **23 backend controller files and 144 declared HTTP routes**, checked against current frontend API modules, shared cursor helpers, hooks, and component callers. Controller declarations were parsed using the installed TypeScript parser; dynamic financial report kinds and warehouse-transfer action paths were expanded to their finite supported values. The graph was used for navigation, then current source was read to verify contracts. The older October integration report was context only, not the current endpoint authority.

- **Source linked** means a matching verb/path and a frontend caller chain were found. This is not a successful HTTP transaction or proof that every UI state is reachable.
- **Helper only** means an API/hook is present but this inspection found no active component caller. It is not automatically a defect.
- **Backend capability** means no frontend wrapper/action was found. Such a route is only disconnected if an agreed active workflow requires it.
- **Infrastructure** means a probe or operational route does not require a business screen.
- **Runtime verified** requires execution against a running service. No row below has that designation. Mock-backed tests can verify mappings/guards but cannot establish database persistence or deployed configuration.

The UI column uses module-resolved function references from a matching API wrapper or an actual literal resource-path caller. Shared cursor helper names are never joined across every consumer. API aliases and hook re-exports used by staffing and master-data forms were separately inspected. Traversal stops at the first component; this establishes a source reference, not a role-by-role browser walkthrough or proof of an action being exercised. Relative backend source links point to the sibling checkout. See [PRODUCTION_READINESS_AUDIT.md](PRODUCTION_READINESS_AUDIT.md) for final runtime results, corrections, and release gates.

## Auth and permission findings

No confirmed authentication bypass or missing business-controller guard was found in the inspected tree. Every business controller applies JWT plus role guards; financial reports require ADMIN and audit events SUPERADMIN. Login, the root status response, and health probes are intentionally public. Backend roles remain authoritative even where frontend controls hide actions.

## Residual risks and deployment checks

These are deployment or policy review items, not claims of a demonstrated compromise. They were not changed speculatively.

| Severity | Observation and evidence | Required follow-up / limit |
| --- | --- | --- |
| Medium, conditional | The application bootstrap [main.ts](../erjv-backend/src/main.ts) contains no HTTP security-header middleware, and frontend [vercel.json](vercel.json) declares rewrites without a header policy | Verify actual edge responses for CSP, frame restrictions, MIME protection and HTTPS/HSTS. Edge settings were unavailable; absence in source does not prove absence in deployment. Select/test a CSP against the rendered app before enabling it. CWE-693 / OWASP A05 |
| Medium, policy | [auth.service.ts](../erjv-backend/src/auth/auth.service.ts) only calls the account-keyed login throttle after finding an active account; [prisma-login-attempts.ts](../erjv-backend/src/auth/infrastructure/prisma-login-attempts.ts) limits five attempts per 15-minute window | Existing accounts can yield 429 while unknown/inactive accounts yield 401; there is no source-level IP/global throttle. Assess account-enumeration and account-lockout policy and verify edge rate limiting. No live brute-force or enumeration test was performed. CWE-204 / CWE-307 / OWASP A07 |
| Low, defense in depth | Bearer tokens live in localStorage in [AuthContext.tsx](src/features/auth/AuthContext.tsx) | An XSS compromise could read tokens. Preserve input rendering safeguards and validate deployed CSP; changing session transport would require an explicit API/security design decision. No XSS exploit was attempted |
| Deployment prerequisite | [app-config.service.ts](../erjv-backend/src/config/app-config.service.ts) requires database URL and a 32-character JWT secret in production, constrains TTL, validates exact CORS origins and requires TLS options for Supabase | Verify NODE_ENV=production and configured values privately on the host. Other PostgreSQL hosts do not have equivalent TLS enforcement in this source. Empty CORS allowlist fails browser access closed but can make an otherwise healthy deployment unusable |
| Deployment prerequisite | [vite.config.ts](vite.config.ts) requires a production backend HTTPS origin; development uses a local `/api` proxy. Production Swagger is disabled by main.ts | Confirm deployed frontend origin appears in the backend CORS allowlist; do not assume Vercel SPA rewrites proxy API traffic |
| Dependency audit | Root workstream ran npm audit for both trees: initial frontend report had 16 package entries (four high); backend had 36 low/moderate package entries | After the root compatible updates, the frontend audit reports 12 moderate dev-only package entries and zero production dependency findings; the backend reports 36 dev-only entries (3 low, 33 moderate) and zero production dependency findings. The initial lockfile classified follow-redirects and Vite as production-installed and undici/zod as dev-only. Axios uses a browser adapter in this frontend, so follow-redirects installation alone does not show the Node adapter is shipped or executed. Vite affects dev/build/preview tooling even when listed outside devDependencies. All 36 initial backend package entries were dev-only in the lockfile, including Nest CLI/tooling chains; do not equate package-entry totals with distinct exploitable production vulnerabilities. Registry advisories are not an exploit test; no incompatible forced downgrade/major upgrade was applied |

No production URL, authenticated deployed role sessions, or hosted headers/TLS configuration was available to this workstream. The root workstream subsequently ran a fresh guarded local database suite: 242 passed, one seed case skipped; backend unit tests: 582 passed; HTTP tests: 93 passed. These executions verify local behavior, not deployed headers, host configuration, or every UI workflow. The endpoint rows remain source-classified because this matrix did not record per-route live HTTP evidence.
