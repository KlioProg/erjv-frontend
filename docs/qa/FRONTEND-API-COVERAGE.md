## Important contracts and refresh behavior

- Incoming creation whitelists purchaseOrderId, warehouseId, scheduledAt, supplierReference and notes. No items/plannedItems/receivedQuantity/damagedQuantity; scheduling has no unsupported body. Actual receipt item arrays belong to completion.
- Outgoing creation uses a header DTO; planning uses PUT items; dispatch retains salesOrderItemId, stockItemId and loadedQuantity. Completion preserves its actual-delivered item contract. Legacy allocation IDs are not substituted.
- SO/PO draft updates preserve expectedRevision and mutually exclusive fixed/percentage discounts. SO expectedRevision must be at least 1. Fixed-peso SO draft support was confirmed in backend service/DTO source and 18 backend tests, not inferred from a commit message.
- Inventory displays quantity as physical, availableQuantity as available, quarantinedQuantity separately; it never subtracts quarantine twice. Unknown quantities remain distinguishable from zero. Unit-aware product/warehouse context is preserved. Threshold is null or an exact nonnegative Decimal(12,2); capacity uses the same decimal bounds. New products require the actual chosen unit.
- Quarantine CLEAR, REMOVE and DAMAGED/SPOILED correction retain existing routes, partial quantities, mandatory reasons, confirmations and Manager/Admin checks. Hooks refresh stock-items, products, warehouses, quarantine-lots, purchase-orders, incoming-deliveries and outgoing-deliveries on settled writes. No deletion of quarantine history was introduced.
- Domain mutation hooks invalidate their owning list/detail caches. Quarantine and threshold refresh have direct component tests. This is source/test evidence; no claim of fresh browser cache behavior for every mutation.
- Four cursor list helpers normalize cursor envelopes, preserve filters and signals and load further pages. The current database has only 2–5 orders/deliveries per module, so a >50-record live dataset was unavailable; pagination edge cases are automated-test evidence.
