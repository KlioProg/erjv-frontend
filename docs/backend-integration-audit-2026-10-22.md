## Endpoint matrix

Read/list endpoints return arrays or nullable single objects as implemented. `includeInactive=false|true|only` applies to master data; stock items have no archive flag. Order/delivery filters use `status` plus their corresponding entity IDs; the backend lists are unpaginated, so existing frontend DataTable search/sorting/pagination stay local. All secured calls use the shared bearer-token client. ADMIN and MANAGER perform operational writes, STAFF reads; SUPERADMIN inherits ADMIN access in the backend guard. User mutations and registration require ADMIN; account audit reads require SUPERADMIN. The backend additionally protects the single superadmin and last active ADMIN.

### Backend issue requiring verification: receipts after PO cancellation

- Endpoints: `PATCH /purchase-orders/:id/cancel` and `PATCH /incoming-deliveries/:id/complete`.
- Expected: completing a shipment must not add inventory to a cancelled purchase order or resurrect that order.
- Source finding: `PurchaseOrdersService.cancel` checks order status and recorded stock movements, but not scheduled incoming deliveries. `IncomingDeliveriesService.complete` checks the shipment status, applies incoming stock, then calls `refreshReceiptStatus` without revalidating the parent order. That refresh can replace CANCELLED with RECEIVED/PARTIALLY_RECEIVED.
- Reproduction for the backend developer: create and confirm a PO; create/schedule an incoming delivery without receiving it; cancel the PO; complete the incoming delivery; inspect inventory and PO status. **Not executed against a live database here.**
- Required backend decision/fix: enforce the parent order lifecycle transactionally during cancellation and receipt, rejecting the inconsistent transition or explicitly cancelling dependent shipments; add a regression/concurrency test. Frontend requests match the current DTOs, but these two endpoints remain **Partially Connected** until this lifecycle edge case is verified/fixed.

Production connectivity also needs a real `VITE_API_BASE_URL` and verified backend CORS or a same-origin proxy. No CORS configuration was found in this backend source; the Vite development proxy is already configured. This audit does not certify a deployed environment.
