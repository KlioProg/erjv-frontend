# Frontend production UI/UX audit

Date: 18 October 2026

## Verdict: READY WITH CONDITIONS

The source and automated interaction review supports proceeding to release acceptance testing. It does **not** establish full production UI/UX signoff. Confirmed shared keyboard and data-loading problems were repaired. Desktop/mobile visual acceptance, rendered accessibility, and authenticated journeys against real services remain required.

No P0 issue was confirmed in this review. Three groups of P1 defects were confirmed and fixed below. This is not evidence that untested journeys contain no P0/P1 defects.

## Coverage and evidence

Inventoried all route declarations in `src/routing/AppRoutes.tsx`, route helpers, the authenticated shell, and the direct components for every routed screen. Reviewed major shared primitives, data loading/error branches, forms, confirmation flows, navigation, order composition, stock presentation, and delivery scheduling/details. Reviewed the existing tests for operational safeguards and ran the unit/component suites. Component tests use jsdom and test-only service adapters; they do not prove actual browser layout or backend behavior.

## Existing strengths preserved

- A canonical `DataTable` provides sorting, pagination, loading announcements, named pagination controls, and consistent row actions.
- Shared management headings/toolbars, status navigation, semantic tokens, locally hosted Inter, and restrained surfaces give the routed product a coherent operational identity.
- Radix supplies modal/menu foundations. Delivery/order composers already distinguish busy states, validation, missing reference data, and retry paths.
- Existing tests cover exact decimal stock/money, unavailable stock, draft versus confirmed orders, partial deliveries, vehicle/driver reservations, archived records, and permissions. These behaviors were preserved.
- Location stock warnings provide actionable navigation rather than relying on color alone.

New tests were first observed failing for the original defects, then passing with their fixes. An earlier run under concurrent build/lint load hit one 5-second timeout in the existing draft-order workflow; its isolated suite and the final full run passed without changing timeouts or disabling tests.
- `npm run lint`: zero errors; one existing unused eslint-disable warning in the user's toolkit `scripts/axe_audit.mjs`.
- `npx eslint src`: passed without warnings or errors.
- Production build and TypeScript: pass with the process-only validation origin `VITE_API_BASE_URL=https://build-check.invalid`. This is not a configured or tested production API. The unconfigured build correctly fails its existing HTTPS-origin requirement. No environment file was changed.
- Production bundle: approximately 913 kB JavaScript, 257 kB gzip; Vite reports its existing large-chunk warning.
- Formatting and diff whitespace: checked for changed application/test files.
- An additional read-only review caught the keyboard-open dropdown case; its regression test reproduced the issue before the final fix.

### UX/UI gates: actual outcomes

Used MCP `get_doctrine` for accessibility, review, and components, plus `list_gates`, `run_gate`, and `review_ui`.

- MCP `axe_audit` with a localhost URL did not measure anything: that runner expects a local target path.
- MCP `validate_contrast` and `review_ui` failed to execute their Python gates (exit 9009, Python unavailable in the MCP process). `review_ui` printed **0/7 gates passed**. This is an infrastructure failure, not seven measured application defects and not a pass.
- Browser inventory returned no browser, and opening an in-app browser returned “Browser is not available: iab.”
- Local `verify_responsive` and `axe_audit` with `DS_REQUIRE_BROWSER=1` failed because Playwright is not installed. No browser dependencies were installed, and no visual/a11y browser result is claimed.
- The local Python launcher could not locate an interpreter. Running the existing toolkit scripts with the known Python executable and UTF-8 mode worked.
- Local `validate_theme_refs` scanned the source and flagged three unresolved Radix variables. These are runtime-provided variables: dropdown available height and select trigger width/height. The installed Radix implementations define them in their content styles. Recorded as scanner limitations; the gate itself is **not** reported as passing. No fake CSS definitions were added to silence it.
- Local `contrast.py`: `#1c211d` on `#80b918` = **6.91:1**, AA normal text PASS; `#ffffff` on `#4d7337` = **5.49:1**, AA normal text PASS. These two source-color pairs do not establish rendered, hover/focus, dark-theme, or application-wide WCAG compliance.

## Remaining risks and release acceptance

1. **Release condition — real browser acceptance:** Inspect desktop, landscape tablet, and mobile, including 320px widths and enlarged text. Verify sidebar breakpoint changes, long breadcrumbs, pagination, long values, horizontal table scrolling, popup positioning, soft keyboards, dialogs, and focus indicators. These have not been visually inspected.
2. **Release condition — real services and roles:** Supply the actual production HTTPS API origin and exercise sign-in/session expiry, permitted/read-only roles, create/edit/archive/restore, draft/confirm/cancel, incoming receiving, outgoing scheduling/dispatch/arrival, stock warnings, failed requests, and partial states using authorized test records. No live records were created or changed during this audit.
3. **Release condition — rendered accessibility:** Run axe and applicable keyboard, focus-trap, contrast/state, overflow, responsive, and target-size checks in a browser against the actual app. Complete manual screen-reader checks; jsdom coverage is insufficient for signoff.
4. **P2 — pending form dismissal consistency:** Several older master-data/stock forms disable their Cancel/Save buttons while submitting but still let their outer dialog close through X/Escape/outside interactions (for example `StockAdjustModal.tsx` and `ClientModal.tsx`). A save may finish after dismissal. Align those forms with the existing busy delivery/order dialogs and test delayed success/failure before rollout to slow connections. This pass did not restructure those form/dialog ownership boundaries.
5. **P2 — initial-load performance:** The app remains eagerly bundled. Measure actual cold-load performance on operational devices/networks before deciding on route splitting. No runtime performance result is claimed from bundle size alone.

No broad redesign or dependency installation was performed to satisfy toolkit preferences. In particular, the named native page-size selector and existing operational table patterns were retained.
